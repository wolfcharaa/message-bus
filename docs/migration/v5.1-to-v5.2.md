# Migration from v5.1 to v5.2

v5.2 is backward-compatible with v5.1 runtime and PostgreSQL schema. The release adds registry diagnostics, a richer compile CLI and contextless `DomainHandler` bindings.

## Required actions

No database migration is required.

After updating the package, rebuild the compiled registry artifact. New bindings contain explicit `role` and `invocationMode` metadata. v5.2 can still read old v5 bindings and defaults them to application/context-aware behavior.

```bash
composer update romanfedorskij/message-bus
vendor/bin/message-bus registry:compile \
  --bootstrap=config/message_bus_registry.php \
  --output=var/cache/message_bus_registry.php
```

## New compile bootstrap

The recommended bootstrap returns `RegistryCompileInput` so CLI options can control compilation and diagnostics:

```php
<?php

declare(strict_types=1);

use Wolfcharaa\MessageBus\Cli\RegistryCompileInput;
use Wolfcharaa\MessageBus\Discovery\ComposerClassMapProvider;

return new RegistryCompileInput(
    provider: new ComposerClassMapProvider(
        classMapFile: __DIR__ . '/../vendor/composer/autoload_classmap.php',
        namespacePrefixes: ['App\\'],
    ),
);
```

The old bootstrap form returning `MessageRegistryDefinition` remains supported in v5.2.

For CI, use:

```bash
vendor/bin/message-bus registry:compile \
  --bootstrap=config/message_bus_registry.php \
  --output=var/cache/message_bus_registry.php \
  --fail-on-warning \
  --deprecations=fail
```

Use `--explain` when compilation fails to print the affected `message -> handler -> flow` graph.

## Domain handlers

`DomainHandler` is optional. Use it for a small synchronous domain operation that must not receive `MessageContextInterface`:

```php
use Wolfcharaa\MessageBus\Attribute\DomainHandler;

#[DomainHandler(message: FindAddress::class)]
final class FindAddressHandler
{
    public function __invoke(FindAddress $message): AddressResult
    {
        // ...
    }
}
```

The default flow is `domain_capability`. If the application provides a custom `FlowRegistry`, add that sync flow explicitly or select another registered sync flow on the attribute. Async domain handlers are rejected during compilation.

Keep nested `dispatch()`/`publish()`, cross-capability ordering and use-case orchestration in regular context-aware handlers.

## Middleware deprecations

The old `Middleware` API still works. The default deprecation mode is `ignore`, so existing production builds stay quiet.

- `--deprecations=warn` reports legacy usage and keeps exit code `0`;
- `--deprecations=fail` reports legacy usage as an error and prevents registry output;
- new interceptors should type-hint `Wolfcharaa\MessageBus\Interceptor\PipelineInterface`.

Canonical built-in implementation migration from `Middleware\*` to `Interceptor\*` is deferred to the next major release.
