# Migration v5.2 to v6

v6 is a breaking release. PostgreSQL queue and worker-control schema do not change, but the compiled registry schema changes from `5` to `6`, so every project must rebuild its registry artifact.

## Dispatch contract

`dispatch()` remains the only sync API.

- `QueryHandler` is the only handler kind that returns a business result.
- `CommandHandler` executes processing rules and must return `void`.
- A message must not have both a sync query handler and a primary sync command handler.

Before:

```php
#[CommandHandler(message: CreateUser::class)]
final class CreateUserHandler
{
    public function __invoke(CreateUser $message, MessageContextInterface $context): CreateUserResult
    {
        // ...
    }
}
```

After, when application code needs a result:

```php
#[QueryHandler(message: CreateUser::class)]
final class CreateUserHandler
{
    public function __invoke(CreateUser $message, MessageContextInterface $context): CreateUserResult
    {
        // ...
    }
}
```

After, when this is a command:

```php
#[CommandHandler(message: CreateUser::class)]
final class CreateUserHandler
{
    public function __invoke(CreateUser $message, MessageContextInterface $context): void
    {
        // ...
    }
}
```

## DomainHandler removal

`DomainHandler` is removed. Use the ordinary handler attribute with `contextAware: false`:

```php
#[QueryHandler(message: FindAddress::class, contextAware: false)]
final class FindAddressHandler
{
    public function __invoke(FindAddress $message): AddressResult
    {
        // ...
    }
}
```

This keeps the library neutral about DDD structure while still enforcing the important runtime rule: contextless handlers cannot receive `MessageContextInterface`.

## Interceptor pipeline

Use `Wolfcharaa\MessageBus\Interceptor\PipelineInterface` for interceptor signatures.

```php
use Wolfcharaa\MessageBus\Context\MessageContextInterface;
use Wolfcharaa\MessageBus\Interceptor\PipelineInterface;

final class AuditInterceptor
{
    public function __invoke(MessageContextInterface $context, PipelineInterface $pipeline): mixed
    {
        return $pipeline->continue();
    }
}
```

`Wolfcharaa\MessageBus\Middleware\PipelineInterface` and the `--deprecations` compatibility switch were removed.

## Registry compile bootstrap

`registry:compile` now requires a bootstrap that returns `RegistryCompileInput` or `RegistryCompilationResult`. A bootstrap returning `MessageRegistryDefinition` no longer gives the CLI enough graph context for diagnostics.

```php
return new RegistryCompileInput(
    provider: $provider,
    flows: $flows,
    libraryVersion: '6.0.0',
    sourceHash: $sourceHash,
);
```

Useful checks:

```bash
vendor/bin/message-bus registry:compile \
  --bootstrap=config/message_bus_registry.php \
  --output=var/cache/message_bus_registry.php \
  --explain
```

When compilation fails without `--explain`, the CLI prints a hint to rerun with graph details.
